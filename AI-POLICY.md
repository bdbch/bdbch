# AI Policy

This is my personal policy around how I use AI tools and technologies. It will outline my principles and values around working with AI and set boundaries on how I interact with humans and AIs.

**I'm not Anti-AI but I think it's important that everyone outlines their own principles and values around AI.**

## Principles

### Do's

- **General Use**
  - I'm using AI tools like ChatGPT or Claude to research topics, rubber duck ideas and brainstorm.
  - I'm using AI tools to improve my writing, grammar and spelling.
  - I'm using AI tools to fix mistakes in my english as a non-native speaker.
  - I'm using AI tools to summarize long texts and documents.
  - I'm using AI tools to better understand written content of other humans when I have difficulties understanding it.
- **Coding Use**
  - I'm using AI coding tools to help me review my own code, find bugs and improve my code quality.
  - I'm using tab completion features in my IDE to speed up my manual coding process.
  - I'm using AI coding tools to search through documentations and find relevant information faster.
  - I'm using AI coding tools to nagivate large codebases and understand how they work.
  - I'm using AI coding tools to help me find missing content in documentations.
  - I'm using AI coding tools to handle boilerplate code or repetitive tasks, so I can focus on more complex work.
    - This includes things like generating types, interfaces or simple functions that are small or trivial enough to be generated by AI without much risk of introducing bugs or errors.
    - I will take responsibility about code I generate with AI and will review it carefully before using it in production.

### Don'ts

- **General Use**
  - I don't use AI tools to write content for me (e.g. blogs, social media posts, etc.).
  - I don't use AI to generate written text for other humans, like messages, emails, social media posts or any other form of communication. See [more](#communicating-with-humans).
  - I don't use AI to automatically generate PR descriptions.
  - I don't use AI to act like I have knowledge or expertise I don't have. I will be honest about my knowledge, skills and experience.
  - I won't use potentially personal or sensitive data of others in AI tools unless I have explicit permission to do so.
- **Coding Use**
  - I don't use AI tools to write code for me in the sense of _vibe coding_ (e.g. "build a todo app in React ...") for any serious work outside of experiments, learnings or demos.
  - I won't use AI to outsource my work, responsibilities or skills to AI tools.
  - I don't use AI tools to automatically reviewing code (my own or others) without also manually reviewing and understanding the code myself.
  - I don't use AI tools to quickly create automated Pull Requests that will strain other humans to review and understand the code without also manually reviewing and understanding the code myself.

## Why those principles?

### Communicating with humans

I believe that communication between humans is a core part of our daily work and life. When I personally talk to someone I expect that person to be a real human being that will give it's personal opinion, knowledge, experience but also taste into a discussion.

I don't expect other humans to just auto-generate messages and send them to me, so that is something I also won't do. Outsourcing human communication to AI can cause big harm to teams, communities and relationships to a point where it can be hard to recover from.

As a maintainer I've seen a lot of auto-generated pull request descriptions. While I'm okay with people using AI to write their code, I at least expect them to write their own PR descriptions and explain to me what their code does, why they wrote it that way or how it works. A auto-generated PR description completely hides if the author actually knows or understands what they actually worked on and makes it harder for me to trust that contributor.

Because I feel this way, and because I think that human communication is important to understand the other person's reasoning & thoughts, I will not use AI to generate any of my own messages, emails, social media posts, pull request descriptions or any other form of communication that is meant to be read by other humans. Anything else would be dishonest and disrespectful to the other person.

### Why I don't use code to completely auto-generate code

When I decided to work in tech, write code & work on products it wasn't primarily because of money or it just being a job. In general I always loved technology, computers and software. AI is a very exciting new technology but at the same time it is something that can suck joy, creativity and learning out of the job I love to do.

At the same time - since I started to use tools like Claude Code, Codex CLI or OpenCode I felt that it's very easy to just outsource thinking and problem solving to AI tools for the sake of having faster results and more output. While this is very tempting, it is something that will make me a worse engineer in the long run and I can just recommend other engineers, specifically juniors to not fall back into the vibe coding trap.

I also don't believe in the _"I don't read code anymore"_ mentality that some people have started to bring up on social media. That's like a chef saying _"I don't taste my food anymore because I have a robot that completely cooks it for me"_.

Some people even bring up that Linus Torvald now is pro AI even on Linux kernel development but I don't think they get Linux actual point. Linux is a very experienced developer so a tool like AI is something that he can perfectly use to his advantage. He also repeatedly said that AI should be used as **a tool to help humans** and not to generate vibe coded AI slop for humans to blindly accept because the result looks correct.

Because I value my job, the profession I picked and I still believe being the one controlling my codebase is the right choice, I won't use AI anymore to generate whole features or products for me but I will use it more as a tool to do specific things when I need them.

**This may sound like I will be slower on purpose** but I think that

1. It won't be necessarily slower considering that I still use AI in a more granular way to help me with specific tasks
2. The value of still learning, becoming better and being the one in control of my codebase and
3. The value of still enjoying my job and work is more important than just being faster and having more output.

### AI in Open Source

As I mentioned already, using AI is absolutely fine. However people contributing to open source projects should always be aware that there is a a human or multiple humans behind a project that have put a lot of time, effort and love into the project.

Every pull request you send to a project means that you are asking a human to review, understand and merge your code. Sending multiple pull requests with auto-generated code, PR descriptions and messages is not only disrespectful to the maintainers but also makes it harder for them to work with you.

Because of that, I will stay away from contributing to open source projects with auto-generated code, specifically if I don't understand the project or code myself. I will also be more critical of PR's and contributors on my own projects.
